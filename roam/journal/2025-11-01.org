  - *Permanent Branches:*
    - =main= (or =master=) - Production-ready code
    - =develop= - Integration branch for features
*Temporary Branches:*
- Feature branches - New features or enhancements
- Bugfix branches - Non-critical bug fixes
- Hotfix branches - Critical production fixes
- Release branches - Prepare for production releases
- Chore branches - Maintenance tasks (refactoring, dependencies, tooling)
** Professional Naming Convention
Here's a naming scheme that scales well:
#+begin_src markup
<type>/<ticket-id>-<short-description>

#+end_src
*Examples:*
#+begin_src markup
feature/PROJ-123-user-authentication
feature/PROJ-456-payment-gateway-integration
feature/PROJ-789-dark-mode-toggle

bugfix/PROJ-234-fix-login-redirect
bugfix/PROJ-567-correct-date-formatting

hotfix/PROJ-999-security-patch
hotfix/PROJ-888-payment-failure

release/v2.3.0
release/v1.5.1

chore/PROJ-345-update-dependencies
chore/PROJ-678-refactor-api-service
chore/setup-ci-pipeline

#+end_src
*Key principles:*
- Use lowercase and hyphens (not underscores or spaces)
- Include ticket/issue numbers when applicable
- Keep descriptions concise but meaningful
- Be consistent across the team
*Branch Workflow:*
1. Create feature branches from =develop=
1. Merge completed features back to =develop=
1. Create release branches from =develop=
1. Merge releases to both =main= and back to =develop=
1. Create hotfixes from =main=, merge to both =main= and =develop=
This system keeps your repository organized and makes it easy to understand what each branch is for at a glance.
