Your plan is solid, and the cleanest way to do it is: *use OB‑Xa V’s internal MIDI Learn + a dedicated MPK249 preset, and tell Ableton to ignore the MPK for global “Remote” control.*
Below is how I’d set it up, step by step.
-----

** 1. Make Live ignore the MPK for mixer/track stuff
You want the MPK to talk /only/ to OB‑Xa V, not to Live’s mixer, sends, etc.
1. In Ableton, go to *Preferences → Link/Tempo/MIDI → MIDI*.
1. In the *Control Surfaces* section, remove any MPK249 entry (set it to =None=) so Live doesn’t use the Akai remote script or auto‑mapping.[1][2]
1. In the *MIDI Ports* section, for the *MPK249 Input*:
  - Turn *Track = On* (so notes and CCs go into tracks/devices).[3][1]
  - Turn *Remote = Off* (this stops Live from using those CCs to map to track volumes, sends, etc.).[4][1]
  - Leave *Sync = Off* unless you explicitly need clock.[1]
Now Live will pass the MPK’s MIDI /into/ instrument tracks, but won’t try to map its knobs/faders to the GUI.
-----

** 2. Create a dedicated MPK249 preset for OB‑Xa V
On the MPK249, you want a preset where *all knobs/faders/buttons send CCs on a chosen MIDI channel*, and you never reuse this preset for anything else.
From the MPK249 manual: presets store how the faders, knobs, buttons, and pads behave, including MIDI channel and CC assignments.[5]
1. Put the MPK249 into *Preset Mode* and pick an empty slot (e.g. Preset 20).[5]
1. Edit the *Assignable Knobs*:
  - Type: set to *MIDI CC*.
  - Choose a *MIDI channel* (e.g. channel 2) for all of them.
  - Assign CC numbers you’re unlikely to use elsewhere (e.g. 20–31).[5]
1. Edit the *Assignable Faders* similarly (type = MIDI CC, same MIDI channel, different CC range, e.g. 40–47).[5]
1. Optionally set the *Assignable Switches* to CCs (for on/off parameters: sync, unison, etc.).[5]
1. Save the preset with a name like =OBXa_ONLY= on the MPK.[5]
This gives you a “hard‑wired” OB‑Xa layout that you won’t accidentally repurpose.
-----

** 3. Set up the OB‑Xa V track in Ableton
1. Create a *new MIDI track* in Live.
1. Drop *OB‑Xa V* on that track.
1. In the track’s I/O:
  - =MIDI From=: select *MPK249* and, if you used a specific MIDI channel, set it to that (e.g. =MPK249 / Ch. 2=).[6][1]
  - =Monitor=: set to *In* (or Arm the track) so the plugin always hears the MPK.[3][1]
At this point, OB‑Xa V is getting the raw CC and note data from the MPK, and Live itself is not using those CCs for anything else.
-----

** 4. Use OB‑Xa V’s internal MIDI Learn
OB‑Xa V has a dedicated *MIDI tab* with a Learn system: when you enable it, all MIDI‑assignable controls turn purple, and existing assignments are red.[7][8]
1. Open OB‑Xa V’s side panel and go to the *MIDI tab*.[7]
1. Click the *Learn* button to enter MIDI Learn mode:
  - Assignable controls turn *purple*, assigned ones are *red*.[7]
1. Click a *purple* parameter you want to control (e.g. filter cutoff).[7]
1. Move the corresponding knob or fader on the MPK249.
  - The control in OB‑Xa V turns red and the assigned CC number shows in the list.[7]
1. Repeat for each parameter you care about:
  - Knobs for filter, envelopes, LFO, etc.
  - Faders for mixer levels, oscillator levels, etc.
1. To unassign something, right‑click / ctrl‑click it and choose the unassign option.[7]
OB‑Xa V also lets you set a specific *MIDI channel* it listens on (or ALL/omni), so you can match the channel you used on the MPK249.[7]
-----

** 5. Save the OB‑Xa V MIDI configuration (so it’s reusable)
Arturia instruments let you save and manage *MIDI controller configurations* separate from presets, and you can export/import or set one as default.[9][10][7]
1. In the OB‑Xa V MIDI tab, open the *MIDI Config* menu (usually a dropdown in that tab).[10][7]
1. Use *Save As* to store your mappings under a clear name like =MPK249_OBXa=.[9][10]
1. If available, choose *Set as Default* so every new OB‑Xa V instance starts with this mapping.[10][9]
1. Optionally *Export* the config file as a backup.[10]
Now switching patches inside OB‑Xa V won’t mess with your hardware mapping; the MIDI config stays consistent across presets and instances (subject to the DAW saving plugin state).[10][7]
-----

** 6. Save a Live preset/template so you don’t redo routing
Because Live doesn’t save “MIDI mappings to Configure Mode parameters” globally, it’s better to save the plugin + routing as a device preset or rack.[11][12]
1. On that OB‑Xa V track (with routing set up and your MIDI config saved in the plugin):
  - Option A: Drag the *OB‑Xa V device title bar* to the User Library to save a device preset.
  - Option B: Put OB‑Xa V in an *Instrument Rack* and drag the rack to the User Library (useful if you add FX/macros later).[12][11]
1. Optionally save a full *Live Set* called something like =OBXa_Controller_Template.als= with this track preconfigured.[11]
Then, whenever you want that “dedicated OB‑Xa controller” behavior, you just load this preset/rack or template set; no extra mapping in Live itself.
-----

** 7. Physical labeling & workflow
Now you can do your console‑tape plan:
- Put the MPK249 on the =OBXa_ONLY= preset.[5]
- Label each knob/fader with its assigned OB‑Xa V parameter (cutoff, res, env amt, etc.).
- If you run out of controls, consider mapping OB‑Xa V’s *Macro knobs* as “meta” controls (e.g., macro = “brighten”, controlling cutoff + env + osc mix) and give those prime real estate on the MPK.[7]
From here, your workflow is:
1. Open Ableton.
1. Load your OB‑Xa V preset/rack or template track.
1. Put MPK249 into =OBXa_ONLY=.
1. Jam — all controls talk only to OB‑Xa V, not to Live’s mixer or global UI.
If you want, tell me roughly how you’d like to distribute controls (e.g. “all 8 faders for oscillator + filter levels, knobs for envelopes/LFO”) and I can propose a concrete control layout that will feel good under the hands.
