    - *Initialize Claude Code in the Project*
      - Run the =forward/init= command in the project root.
      - This command scans the entire codebase, including folder structure, application start method, state management, etc.
      - It generates a =claude.md= file summarizing the project structure, frameworks, libraries, and development commands in a human-readable format.
      - Confirm creation of the =claude.md= file when prompted.
      - [[https://www.youtube.com/watch?v=i_OHQH4-M2Y&t=30][(00:00:30)]]
    - *Review and Update the *[[claude.md][*claude.md*]]* File*
      - Open the generated =claude.md= file in the project root.
      - Check the architecture overview, project structure, data architecture, styling, testing setup, and development notes.
      - Manually update the file if necessary, especially if starting with a new project or adding new folders (e.g., add a =hooks= folder if you plan to create hooks).
      - Keep this file up-to-date and track it with version control so all developers share the same guidance.
      - [[https://www.youtube.com/watch?v=i_OHQH4-M2Y&t=120][(00:02:00)]]
    - *Add Memories to *[[claude.md][*claude.md*]]* for Project-Specific Guidance*
      - Use the hash symbol =#= in the chat session to add memories or instructions.
      - Choose to save memories to project memory (recommended), local project memory, or global memory.
      - Project memory updates the =claude.md= file and is shared with the team.
      - Example: Add a memory like "When making new page components, always add a link to that page in the header."
      - [[https://www.youtube.com/watch?v=i_OHQH4-M2Y&t=300][(00:05:00)]]
    - *Create New Features Using Claude Code*
      - Ask Claude Code to create new components, hooks, or pages by typing your request in the chat.
      - Example: Request a hook to store the user's theme preference and save it in local storage.
      - Specify if you do not want the new feature to be used anywhere yet to avoid unwanted automatic usage.
      - Claude Code will refer to the =claude.md= file to place new files in the correct folders (e.g., create a =hooks= folder if it doesn't exist).
      - Review and accept the generated code changes.
      - [[https://www.youtube.com/watch?v=i_OHQH4-M2Y&t=390][(00:06:30)]]
    - *Test New Features and Verify Integration*
      - After Claude Code creates new components or pages, test them in your development environment or browser.
      - For example, create a new "About" page with a title and content, and verify that Claude Code adds a link to the header navigation automatically if instructed.
      - Accept any additional file edits Claude Code proposes to integrate the new feature properly.
      - [[https://www.youtube.com/watch?v=i_OHQH4-M2Y&t=510][(00:08:30)]]
    - *Manage and Edit Memory Files*
      - Use the =/memory= command to open and edit memory files (=claude.md= files) directly in your editor.
      - Select which memory file to edit: project memory, local project memory, or global memory.
      - Edit these files to add or update guidance, tooling preferences, or code style notes.
      - Note: Local memory is being deprecated in favor of importing untracked files into project memory.
      - [[https://www.youtube.com/watch?v=i_OHQH4-M2Y&t=600][(00:10:00)]]
    - *Maintain *[[claude.md][*claude.md*]]* for Best Results*
      - Regularly update the =claude.md= file whenever you change project structure, add or remove packages, or modify coding conventions.
      - This ensures Claude Code stays aligned with the current state of your project and generates code accordingly.
      - Share the updated =claude.md= file via version control so all team members benefit from consistent guidance.
      - [[https://www.youtube.com/watch?v=i_OHQH4-M2Y&t=690][(00:11:30)]]

  Benefits of This Approach
  -----
  
  /(Timestamp reference for this explanation: /[[https://www.youtube.com/watch?v=BJX6uJHIz5U][/00:03:00/]]/)/
  - Slash commands are predefined commands you can invoke within Cloud Code to perform specific tasks quickly.
  - They help automate interactions, such as fetching documentation or running code snippets.
  - *Context 7 contains up-to-date documentation for thousands of libraries*, including Cloud Code itself.
  - Instead of manually searching or browsing documentation, you use slash commands to *query Context 7 directly from Cloud Code*.
  - This allows you to *retrieve, compile, and organize documentation or command lists efficiently*.
  - The user instructs Claude Code (via a slash command) to *research all available slash commands related to Cloud Code* using the Context 7 documentation.
  - Claude Code then *automatically compiles a comprehensive list of these slash commands along with explanations* into a markdown file named =CC commands.mmarkdown=.
  - This file serves as a *centralized, easy-to-reference resource* for all slash commands you can use in Cloud Code.
  - It *saves time and effort* by automating the documentation gathering process instead of manually collecting and formatting the commands.
  1. *Query Context 7 for Cloud Code documentation* to get the latest info on slash commands.
  1. *Prompt Claude Code with a task* like:
    
    #+begin_src markup
    Do some research on code with a list of all the slash commands plus explainers saved to CC commands.mmarkdown
    
    #+end_src
  1. Claude Code uses the Context 7 docs to *extract relevant slash commands and explanations*.
  1. It *compiles this information into the markdown file* =CC commands.mmarkdown=.
  1. You can then *open and use this file as a reference* for all slash commands available in Cloud Code.
  - *Automates documentation compilation* — no manual searching or formatting needed.
  - *Keeps documentation up-to-date* by pulling from the latest Context 7 data.
  - *Improves productivity* by having a ready-made command reference.
  - *Integrates seamlessly* into your Cloud Code workflow.
