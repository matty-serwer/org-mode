** 1. Basic usage pattern in Next.js
In your existing Next.js app:
1. Install your package:
  
  #+begin_src bash
  npm install @lupine-tech-design/pedal-ui
  #+end_src
1. Import and use components:
  
  #+begin_src tsx
  // e.g. app/page.tsx or src/app/page.tsx (App Router)
  import { Button } from '@lupine-tech-design/pedal-ui';
  
  export default function Page() {
    return <Button>Test button</Button>;
  }
  #+end_src
This is the standard “download a package from the registry and use it in your project” flow described under *Getting packages from the registry* and *Using npm packages in your projects*.[2][1]
** 2. Things your package.json should support
For a smooth experience in a Next.js consumer, your published =package.json= (of =@lupine-tech-design/pedal-ui=) ideally has:
- A ="main"= field pointing to the CommonJS build (e.g. ="dist/index.js"=).
- A ="module"= or ESM export pointing to ="dist/index.mjs"= (or using ="exports"=).
- ="types"= pointing to ="dist/index.d.ts"= (or =index.d.mts=).[1]
- ="peerDependencies"= that include at least:
  - ="react"=
  - ="react-dom"=
  - optionally ="next"= if you rely on Next-specific APIs.[3][4]
If you paste your =package.json=, it becomes possible to confirm or tweak these fields so Next.js can resolve the module cleanly.
** 3. Client components and Next.js specifics
Because your build log shows ="use client"= being stripped during bundling, the library effectively ships as regular React components.[5]
In a Next.js app (especially App Router):
- If components should always run on the client, import them into a client component file that starts with:
  
  #+begin_src tsx
  "use client";
  
  import { Button } from '@lupine-tech-design/pedal-ui';
  #+end_src
- If your library internally uses things like browser APIs or React hooks, they will work as long as they are only rendered in client components in the consumer app.[6]
If your library itself imports =next/link= or =next/image=, then adding =next= as a *peerDependency* (not bundled) is recommended so the consuming Next app provides it.[7][3]
** 4. Styles from the library
Your tarball includes =src/styles/theme.css=, so the consumer needs a way to load those styles:
- Either you expose a top-level CSS entry to import:
  
  #+begin_src ts
  import '@lupine-tech-design/pedal-ui/styles.css';
  #+end_src
- Or your README instructs users to import =theme.css= in their =app/layout.tsx= or =_app.tsx=:
  
  #+begin_src ts
  import '@lupine-tech-design/pedal-ui/dist/theme.css';
  #+end_src
Next.js supports importing global CSS from certain entry files; this is part of its third-party library guidance.[6]
