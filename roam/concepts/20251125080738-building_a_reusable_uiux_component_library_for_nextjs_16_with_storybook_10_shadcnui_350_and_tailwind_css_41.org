*Storybook 10's ESM-only architecture, combined with Tailwind CSS v4's CSS-first configuration and shadcn/ui 3.5.0's React 19 support, provides the modern foundation for building a production-ready component library.* This comprehensive guide covers the complete setup for "Vet Sweet," a veterinary practice management SaaS requiring components for patient management, scheduling, SOAP notes, and clinical workflows. The approach enables sharing components across multiple Next.js applications while maintaining design system consistency and developer experience excellence.

** Storybook 10 installation and Next.js 16 framework integration
Storybook 10 shipped in November 2025 with *ESM-only support*, reducing installation size by 29% while improving build performance. The recommended framework adapter is =@storybook/nextjs-vite=, which eliminates Webpack and Babel dependencies entirely.
*Installation commands:*
#+begin_src bash
# Initialize Storybook in a Next.js 16 project
npx storybook@latest init

# Or upgrade existing installation
npx storybook@latest upgrade

# Install Vite-based adapter (recommended)
npm install --save-dev @storybook/nextjs-vite @storybook/addon-essentials @storybook/addon-a11y @storybook/addon-interactions @storybook/addon-themes

#+end_src
The *main.ts configuration* requires explicit framework specification with Next.js 16 App Router support enabled:
#+begin_src typescript
// .storybook/main.ts
import type { StorybookConfig } from '@storybook/nextjs-vite';

const config: StorybookConfig = {
  framework: '@storybook/nextjs-vite',
  stories: [
    '../src/**/*.mdx',
    '../src/**/*.stories.@(js|jsx|ts|tsx)',
    '../components/**/*.stories.@(js|jsx|ts|tsx)',

    '@storybook/addon-essentials',

** Tailwind CSS v4.1 CSS-first configuration with the @theme directive
Tailwind CSS v4 introduces a *CSS-first configuration paradigm* that replaces =tailwind.config.js= with native CSS using the =@theme= directive. Theme variables defined within =@theme= automatically generate both CSS custom properties and corresponding utility classes.
*PostCSS setup for Next.js:*
#+begin_src bash
npm install tailwindcss @tailwindcss/postcss

#+end_src
#+begin_src javascript
// postcss.config.mjs
export default {
  plugins: {
    "@tailwindcss/postcss": {},
  },
};

#+end_src
The *globals.css* file becomes the single source of truth for design tokens. The =@theme= directive creates utilities while =:root= defines semantic variables for theming:
#+begin_src css
/* app/globals.css */
@import "tailwindcss";
@import "tw-animate-css";

/* Dark mode variant using class selector */
@custom-variant dark (&:where(.dark, .dark *));

/* Light mode semantic tokens */
:root {
  --radius: 0.625rem;
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --card: oklch(1 0 0);
  --card-foreground: oklch(0.145 0 0);
  --primary: oklch(0.55 0.25 263);
  --primary-foreground: oklch(0.985 0 0);
  --secondary: oklch(0.97 0 0);
  --secondary-foreground: oklch(0.205 0 0);
  --muted: oklch(0.97 0 0);
  --muted-foreground: oklch(0.556 0 0);
  --destructive: oklch(0.577 0.245 27.325);
  --border: oklch(0.922 0 0);
  --input: oklch(0.922 0 0);
  --ring: oklch(0.708 0 0);
  
  /* Vet Sweet custom colors */
  --success: oklch(0.72 0.19 142);
  --warning: oklch(0.84 0.16 84);
  --info: oklch(0.72 0.11 221);
}

/* Dark mode overrides */
.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
  --card: oklch(0.205 0 0);
  --primary: oklch(0.65 0.20 260);
  --muted: oklch(0.27 0.005 265);
  --border: oklch(0.27 0.005 265);
}

/* Connect CSS variables to Tailwind utilities */
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-card: var(--card);
  --color-card-foreground: var(--card-foreground);

  --color-warning: var(--warning);
  --color-info: var(--info);
  --radius-lg: var(--radius);
}

#+end_src
The =@theme inline= directive is essential when referencing CSS custom properties—it ensures utilities resolve to the variable value rather than a static theme value. *OKLCH color space* replaces HSL as the default in Tailwind v4, providing wider gamut support and perceptually uniform color manipulation.

** shadcn/ui v3.5.0 CLI setup and components.json configuration
shadcn/ui 3.5.0 initializes projects with *Tailwind v4 by default* and updates all components for React 19 compatibility. The =forwardRef= pattern is replaced with =data-slot= attributes, and the animation library changed from =tailwindcss-animate= to =tw-animate-css=.
*Initialization:*
#+begin_src bash
npx shadcn@latest init -b neutral --css-variables

#+end_src
The *components.json* file controls CLI behavior and path resolution:
#+begin_src json

  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "app/globals.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""

  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  },
  "iconLibrary": "lucide"

#+end_src

** Component organization and barrel exports pattern
*Barrel exports* aggregate component exports while preserving tree-shaking capabilities. Each component folder contains its implementation, types, stories, and local export:
#+begin_src typescript
// src/components/patient-card/patient-card.tsx
import * as React from 'react';
import { cn } from '@/lib/utils';
import { Card, CardHeader, CardContent } from '../ui/card';
import { Badge } from '../ui/badge';
import { Avatar, AvatarImage, AvatarFallback } from '../ui/avatar';
import type { PatientCardProps } from './patient-card.types';

export function PatientCard({ 
  patient, 
  status, 
  className, 
  ...props 
}: PatientCardProps) {
  return (
    <Card className={cn("w-full", className)} {...props}>
      <CardHeader className="flex flex-row items-center gap-4">
        <Avatar className="h-16 w-16">
          <AvatarImage src={patient.photoUrl} alt={patient.name} />
          <AvatarFallback>{patient.name.charAt(0)}</AvatarFallback>
        </Avatar>
        <div className="flex-1">
          <h3 className="text-lg font-semibold">{patient.name}</h3>
          <p className="text-sm text-muted-foreground">
            {patient.species} • {patient.breed}
          </p>
        </div>
        <Badge variant={status}>{status}</Badge>
      </CardHeader>
      <CardContent>
        <dl className="grid grid-cols-2 gap-2 text-sm">
          <dt className="text-muted-foreground">Owner</dt>
          <dd>{patient.ownerName}</dd>
          <dt className="text-muted-foreground">Last Visit</dt>
          <dd>{patient.lastVisit}</dd>
        </dl>
      </CardContent>
    </Card>
  );
}

** Conclusion
Building a reusable component library for "Vet Sweet" with Next.js 16, Storybook 10, shadcn/ui 3.5.0, and Tailwind CSS 4.1 requires coordinating several modern tooling paradigms. *The CSS-first configuration approach in Tailwind v4* eliminates JavaScript configuration files, centralizing design tokens in CSS with the =@theme= directive. *shadcn/ui 3.5.0's React 19 compatibility* and OKLCH color space adoption align perfectly with this modern stack.
The *Turborepo monorepo structure* enables sharing the =@vet-sweet/ui= package across the main dashboard, client portal, and any future applications while maintaining independent deployability. *CSF 3.0 story patterns* with play functions provide both documentation and interaction testing, ensuring components behave correctly in clinical workflows where reliability is essential.
Key implementation priorities for veterinary practice management include building robust form components for SOAP notes entry, accessible data tables for patient records with keyboard navigation, and status badges with visual urgency indicators (including animation for critical states). The theming system using CSS custom properties with =@theme inline= enables both light and dark modes while maintaining the consistent "Vet Sweet" brand identity across all applications.
