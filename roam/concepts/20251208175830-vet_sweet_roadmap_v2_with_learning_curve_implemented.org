** Application Overview
*“VetPractice”* - Multi-tenant SaaS for veterinary clinics to manage patients, appointments, medical records, and billing.
*Core Entities*: Clinic (tenant), User (staff), Pet, Owner (client), Appointment, MedicalRecord, Invoice
-----

** Phase 1: Foundation & Core CRUD (Week 1-2)
*Goal*: Solid Spring Boot fundamentals and proper architecture
*** Features to Build:
**** 1.1 Project Setup & Configuration
- Initialize Spring Boot 3.x project (Web, Data JPA, PostgreSQL, Security, Validation)
- Database connection configuration
- Environment profiles (dev, prod)
- Docker Compose for local PostgreSQL
- *Skills*: Project structure, dependency management, configuration management
**** 1.2 Pet Management API
- Create Pet entity (name, species, breed, dateOfBirth, weight, clinicId)
- Pet CRUD endpoints: POST /api/v1/pets, GET /api/v1/pets, GET /api/v1/pets/{id}, PUT /api/v1/pets/{id}, DELETE /api/v1/pets/{id}
- Proper controller → service → repository layering
- *Skills*:
  - RESTful API design
  - Spring MVC annotations (@RestController, @RequestMapping)
  - Dependency injection (@Autowired, constructor injection)
  - JPA basics (@Entity, @Id, @GeneratedValue)
  - HTTP status codes & ResponseEntity
**** 1.3 Owner (Client) Management
- Owner entity (firstName, lastName, email, phone, address, clinicId)
- Owner CRUD endpoints
- One-to-Many relationship: Owner → Pets
- *Skills*:
  - JPA relationships (@OneToMany, @ManyToOne)
  - Cascade operations
  - Lazy vs Eager loading
  - Understanding bi-directional relationships
**** 1.4 DTOs & Validation
- Create separate DTOs for request/response (PetCreateDTO, PetResponseDTO, OwnerDTO)
- Add validation annotations (@NotNull, @Email, @Pattern, @Size)
- Custom validation messages
- *Skills*:
  - DTO pattern (why separate from entities)
  - Bean Validation API
  - Mapping between entities and DTOs (manually or MapStruct)
  - Input validation best practices
**** 1.5 Exception Handling
- Custom exceptions (ResourceNotFoundException, ValidationException)
- Global exception handler with @ControllerAdvice
- Standardized error response format
- *Skills*:
  - Spring exception handling hierarchy
  - @ExceptionHandler
  - HTTP error codes (400, 404, 500)
  - Error response structure
*Milestone*: You can create, read, update, delete Pets and Owners with proper validation and error handling. Clean code structure that’s testable.

** Phase 2: Security & Multi-Tenancy (Week 3)
*Goal*: Secure the API and isolate tenant data
*** Features to Build:
**** 2.1 User Authentication
- User entity (email, password, role, clinicId)
- User registration endpoint
- Password encryption with BCrypt
- Login endpoint (username/password → JWT)
- *Skills*:
  - Spring Security basics
  - Password encoding
  - JWT generation (using jjwt library)
  - Authentication flow
**** 2.2 JWT-Based Authorization
- JWT token generation on login
- JWT validation filter (JwtAuthenticationFilter)
- Extract user info from JWT
- Secure endpoints with @PreAuthorize
- *Skills*:
  - Spring Security filter chain
  - JWT structure (header, payload, signature)
  - Token expiration handling
  - SecurityContext and Authentication objects
**** 2.3 Role-Based Access Control
- Define roles: CLINIC_ADMIN, VETERINARIAN, RECEPTIONIST
- Role-based endpoint protection
- Different permissions per role (e.g., only ADMIN can delete)
- *Skills*:
  - @PreAuthorize(“hasRole(‘ADMIN’)”)
  - Method-level security
  - Authorization vs authentication
  - Role hierarchy
**** 2.4 Multi-Tenant Data Isolation
- Clinic entity (name, address, subscriptionTier, isActive)
- Add clinicId to all relevant entities
- Tenant context holder (extract clinicId from JWT)
- JPA filter to auto-scope queries by clinicId
- *Skills*:
  - Multi-tenancy patterns (shared database, row-level)
  - Hibernate @Filter or custom JPA specifications
  - ThreadLocal for tenant context
  - Data isolation security (critical for SaaS)
**** 2.5 Clinic Registration Flow
- New clinic signup endpoint
- Create default admin user for clinic
- Transactional operation (both succeed or both fail)
- *Skills*:
  - @Transactional annotation
  - Transaction boundaries
  - Rollback scenarios
  - Database constraints (unique email)
*Milestone*: Secure API where users must authenticate, data is isolated by clinic, and roles control access.

** Phase 3: Complex Features & Relationships (Week 4-5)
*Goal*: Handle real-world complexity
*** Features to Build:
**** 3.1 Appointment Scheduling
- Appointment entity (petId, veterinarianId, scheduledTime, duration, status, notes)
- Create appointment with validation (no double-booking)
- List appointments (filter by date range, vet, status)
- Update appointment status (SCHEDULED → IN_PROGRESS → COMPLETED)
- *Skills*:
  - Complex queries with JPA Specifications or Criteria API
  - Date/time handling (LocalDateTime, time zones)
  - Business logic validation in service layer

**** 3.2 Medical Records
- MedicalRecord entity (petId, veterinarianId, appointmentId, diagnosis, treatment, prescriptions, createdAt)
- Create medical record (linked to appointment)
- Get pet’s medical history (paginated, sorted by date)
- File attachments (lab results, X-rays) - store file metadata
- *Skills*:
  - Complex entity relationships (Medical Record → Pet → Owner)
  - Pagination (Pageable, Page<T>)
  - Sorting (Sort)
  - Eager fetch optimization (JOIN FETCH)
**** 3.3 File Upload Service
- Upload endpoint for medical record attachments
- Store files in AWS S3 (or local filesystem for learning)
- Return file URL/reference
- Download endpoint with proper headers
- *Skills*:
  - Multipart file upload (@RequestParam MultipartFile)
  - AWS SDK integration (if using S3)
  - File storage patterns
  - Content-Type handling
**** 3.4 Search & Filtering
- Search pets by name, species, owner name (fuzzy search)
- Filter appointments by date range, vet, status
- Combine multiple filter criteria
- *Skills*:
  - JPA Specifications (dynamic query building)
  - JPQL custom queries
  - Performance considerations (indexes)
  - Query optimization
**** 3.5 Audit Trail
- Track who created/modified entities and when
- Add createdBy, createdAt, lastModifiedBy, lastModifiedAt to entities
- Use Spring Data JPA auditing (@CreatedDate, @LastModifiedDate)
- *Skills*:
  - JPA Auditing
  - @EntityListeners(AuditingEntityListener.class)
  - @CreatedBy, @CreatedDate annotations
  - AuditorAware interface
*Milestone*: Complex business features working with proper validation, search, and audit trails. API handles real veterinary workflows.
