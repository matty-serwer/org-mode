#+title: Personal File Index

- Project: macOS File Organization Application
  - *Version:* 1.0 - Initial Ideation
  - *Date:* November 23, 2025
  - *Status:* Concept Development
  - Executive Summary
    - A native macOS application that serves as an intelligent "memory layer" over the file system—creating a project-centric, visually rich directory of file /references/ without ever moving, modifying, or deleting actual files. The app works in tandem with Finder, not as a replacement, helping users remember what they did and what they need to do through meaningful visual organization.
    - *Core Philosophy:* Reference, don't relocate. Augment, don't replace. Remember, don't forget.
  - Core Concept
    - The Problem We're Solving
      - Users interact with hundreds or thousands of files across their Mac, but most file systems are organized by /storage logic/ (folders, dates, file types) rather than by /mental models/ (projects, contexts, deadlines, relationships). Important files get lost in deep folder hierarchies, and users can't remember:
      - "What was I working on last week?"
      - "Which files belong to this client project?"
      - "What's due this Friday?"
      - "Where did I save that mockup with the blue background?"
    - The Solution
      - A workspace application that allows users to:
      -
        1. *Create project-based collections* of file references organized by their mental model
      -
        1. *Drag file links* (not actual files) into organized spaces without touching the source files
      -
        1. *Add contextual memory aids*: notes, images, tags, due dates
      -
        1. *Visualize active work* through colorful, meaningful displays
      -
        1. *Quick-launch files* directly from the app into their native applications
    - What Makes This Different
      - Traditional Approach
        - Moves/copies files
        - File-centric organization
        - Replaces Finder
        - Technical metadata (date, size, type)
        - Static folder structure
        - One file, one location
      - Project Memory Approach
        - Creates lightweight references only
        - Project/context-centric organization
        - Works alongside Finder
        - Mental metadata (notes, images, meaning)
        - Flexible, multi-dimensional organization
        - One file, many contexts
  - Recommended Tech Stack
    - Primary Framework: SwiftUI + AppKit Hybrid
      - *Why This Approach:*
        - Based on current macOS development best practices (2025), a hybrid approach provides the best balance[1][3][4]:
        - *SwiftUI for:* Main UI, modern components, rapid iteration, declarative layouts
        - *AppKit when needed for:* Advanced text editing, drag-and-drop edge cases, file system integration, custom controls
      - *Rationale:*
        - SwiftUI has matured significantly but AppKit is still needed for sophisticated file operations[1][3]
        - SwiftUI offers excellent performance and a cleaner codebase[4][10]
        - AppKit provides battle-tested file system APIs with 25+ years of development[1]
        - Easy to integrate SwiftUI views within AppKit and vice versa[1][4]
    - Language & Tooling
      - Language: Swift 6.1
      - Platform: macOS 15.0+ (Sequoia and later)
      - IDE: Xcode 16+
      - Concurrency: Swift Concurrency (async/await, actors)
    - Key Technologies
      - File Access & Security
        - *Security-Scoped Bookmarks* (Critical)[2][3][11]
        - #+begin_src markup
          // Core technology for persistent file access
          let bookmarkData = try url.bookmarkData(
          options: .withSecurityScope,
          includingResourceValuesForKeys: nil,
          relativeTo: nil
          )
                  - **Why:** macOS sandboxing requires explicit user permission for file access. Security-scoped bookmarks allow you to:
          - Request user permission once via NSOpenPanel
          - Store a secure bookmark reference
          - Regain access to files across app launches without repeated permission dialogs[2][3][11][20]
          #+end_src
        - *Implementation Pattern:*
          -
            1. User drags file into app or selects via open panel
          -
            1. Create security-scoped bookmark from the URL
          -
            1. Store bookmark data (UserDefaults, Core Data, or file)
          -
            1. On app restart, resolve bookmark to URL
          -
            1. Call startAccessingSecurityScopedResource() before use
          -
            1. Call stopAccessingSecurityScopedResource() when done[2][3][11]

  - Critical Technical Challenges & Solutions
    - 1. Sandboxing & File Permissions⚠️ MOST CRITICAL
      - *Challenge:* macOS App Sandbox severely restricts file system access[2][3][6]
      - *Solutions:*
        - *A. Entitlements Configuration*
          - [[com.apple.security][com.apple.security]].app-sandbox
          - [[com.apple.security][com.apple.security]].files.user-selected.read-write
          - [[com.apple.security][com.apple.security]].files.bookmarks.app-scope
        - *B. Progressive Permission Model*[3]
          - *Level 1:* Start with minimal access (app container only)
          - *Level 2:* Request access when user drags first file
          - *Level 3:* Only request broader access if needed
        - *C. Bookmark Management Best Practices*[2][3][11]
          - Create bookmarks immediately when files are added
          - Store bookmark data securely (encrypted if needed)
          - Implement bookmark staleness detection
          - Re-request access gracefully when bookmarks fail
          - Always pair startAccessingSecurityScopedResource() with stopAccessingSecurityScopedResource()
      - *Known Issue to Watch:* macOS Sequoia (15.0-15.0.1) had a critical bug with ScopedBookmarksAgent that could cause hangs[17]. Fixed in 15.1+, but be aware when targeting minimum OS version.
    - 2. File State Tracking
      - *Challenge:* Files may be moved, renamed, or deleted outside your app
      - *Solutions:*
        - Use bookmarkDataIsStale flag when resolving bookmarks[2][5]
        - Implement FileManager notifications for file system changes
        - Graceful degradation: mark references as "unavailable" rather than crashing
        - Periodic validation with user-friendly recovery options
        - Store both URL path and inode information for better tracking[14]
    - 3. Performance at Scale
      - *Challenge:* Managing thousands of file references efficiently
      - *Solutions:*
        - *Lazy loading* of file metadata and thumbnails
        - *Background threads* for bookmark resolution and file queries
        - *Caching* of expensive operations (Quick Look thumbnails, file attributes)
        - *Pagination* for large project views
        - Consider Core Data with proper indexing for complex queries
    - 4. Drag & Drop Reliability
      - *Challenge:* SwiftUI drag-and-drop has platform-specific quirks[23][32]
      - *Solutions:*
        - Test extensively with Finder, Mail, Safari, and other common sources
        - Implement both modern .dropDestination() and legacy .onDrop() if supporting older macOS
        - Add ProxyRepresentation alongside FileRepresentation for better compatibility[32]
        - Provide clear visual feedback during drag operations
        - Handle edge cases: dropping folders, bundles, symlinks
    - 5. CloudKit Sync (Future Feature)
      - *Challenge:* Bookmark data doesn't sync well across devices
      - *Solution:*
        - Store relative paths when possible
        - Re-resolve bookmarks on each device
        - Acknowledge that file references are inherently device-specific
        - Consider "shared project templates" vs. "shared file references"

  - Design Principles
    - UX Principles
      -
        1. *Non-Destructive by Design*
        - Make it impossible to accidentally delete actual files
        - Clear visual distinction between "reference" and "file"
        - Confirmation dialogs for bulk operations
      -
        1. *Finder Harmony*
        - Don't try to replace Finder functionality
        - Complement existing workflows
        - Support "Open in Finder" everywhere
      -
        1. *Visual Memory*
        - Use color, images, and icons extensively
        - Make projects instantly recognizable
        - Support thumbnail previews where appropriate
      -
        1. *Low Friction*
        - Drag-and-drop everywhere
        - Minimal clicks to access files
        - Smart defaults, minimal configuration
      -
        1. *Graceful Degradation*
        - When files move/delete, show gracefully
        - Never lose user's notes/organization
        - Offer recovery options
